# Bug Report — BUG-001

## Summary
Search field accepts special characters without input sanitization warning

| Field | Detail |
|-------|--------|
| **Bug ID** | BUG-001 |
| **Date Found** | 2024-01-15 |
| **Found By** | Luis Elizondo |
| **Module** | Search |
| **Environment** | Chrome 120, Windows 10, OpenCart Demo |
| **Severity** | Medium |
| **Priority** | Medium |
| **Status** | Open |

## Description
When a user enters special characters such as <test> in the search field, the raw characters appear reflected in the URL and page heading without proper encoding.

## Steps to Reproduce
1. Navigate to https://demo.opencart.com
2. Type <test> in the search bar
3. Press Enter

**Expected Result:** Input is sanitized. Characters are HTML-encoded.

**Actual Result:** Raw characters appear reflected without encoding.

## Impact
Reflects a missing output encoding practice that should be addressed as a security hardening measure.

## Suggested Fix
Apply htmlspecialchars() or equivalent output encoding to all user-supplied input.

# Bug Report — BUG-002

## Summary
Cart quantity field accepts negative numbers without validation

| Field | Detail |
|-------|--------|
| **Bug ID** | BUG-002 |
| **Date Found** | 2024-01-16 |
| **Found By** | Luis Elizondo |
| **Module** | Shopping Cart |
| **Environment** | Firefox 121, Windows 10, OpenCart Demo |
| **Severity** | High |
| **Priority** | High |
| **Status** | Open |

## Description
The quantity input field in the cart accepts negative values. When clicking Update with -1, the item is silently removed or the total shows $0.00.

## Steps to Reproduce
1. Add any product to the cart
2. Go to the cart page
3. Change quantity to -1
4. Click Update

**Expected Result:** Validation error: Quantity must be a positive number.

**Actual Result:** No error shown. Item removed or total shows $0.00.

## Impact
Could corrupt order data or allow unintended behavior in checkout totals.

## Suggested Fix
Add min="1" on the input field and server-side validation to reject non-positive values.

# Bug Report — BUG-003

## Summary
Registration form allows submission with mismatched passwords

| Field | Detail |
|-------|--------|
| **Bug ID** | BUG-003 |
| **Date Found** | 2024-01-17 |
| **Found By** | Luis Elizondo |
| **Module** | User Registration |
| **Environment** | Chrome 120, Windows 10, OpenCart Demo |
| **Severity** | High |
| **Priority** | High |
| **Status** | Open |

## Description
When Password and Password Confirm fields contain different values, the form relies only on server-side validation, causing unnecessary server round-trip and poor UX.

## Steps to Reproduce
1. Go to registration page
2. Fill all required fields
3. Enter Password: Password123
4. Enter Password Confirm: Password456
5. Click Continue

**Expected Result:** Immediate inline validation error before form submission.

**Actual Result:** Form submitted to server. Error only appears after full page reload.

## Impact
Poor user experience and unnecessary server requests.

## Suggested Fix
Add JavaScript client-side validation on the Password Confirm field before form submission.
